[STEP 2] Frame-hierarchy driven optimization - Unity 6000.3.22f1, Editor Play Mode
Harness v2 (eval only, no project change): 40 Normal zombies (seed 1234), spawner stopped, player invulnerable and
moving on a circle (r=7m, 0.6 rad/s) so zombies Trace/Attack, recording 10s, first 5 frames skipped, runInBackground=true (runtime).

== Analysis of the baseline recording (1313 frames) =========================================
PlayerLoop incl: avg 4.90, median 4.57, p95 6.02, p99 15.07, max 39.66 ms.  1312/1313 frames < 30 ms, 6 frames > 16.6 ms.
Per-frame inclusive cost in normal frames (ms): rendering 1.8 (Main 0.64 + MiniMap 0.47), Animators.Update 0.59,
  Director.ProcessFrame 0.59, UpdateAllSkinnedMeshes 0.35, UGUI UpdateBatches 0.29 / PlayerUpdateCanvases 0.30, NavMeshManager 0.27.
Worst frames:
  #1793 45 ms : NavMeshManager > Crowd.Avoidance 34.3 ms  (1 frame in 1314; avg 0.037 ms, p99 0.041 ms) -> single outlier, NOT acted on
  #1498 29 ms / #1638 24 ms : UpdateScene + Semaphore.WaitForSignal = Editor-only (scene view) -> not in builds, NOT acted on
Agent config: HighQualityObstacleAvoidance, priority 50, radius 0.25 (left unchanged)

== Change applied ===========================================================================
ZombieHealthBar: canvas component enabled only when the zombie is damaged (Health < MaxHealth) and within
_visibleDistance (15 m, SerializeField) of the player; billboard rotation only while visible.
Verified in play: 0/40 bars visible at full health; after TakeDamage(5) on the nearest zombie -> 1 bar visible.

Caveats
 - Best case for the change: no zombie is damaged in the harness, so every bar is hidden. With all zombies damaged and within 15 m the cost
   returns to ~BEFORE for those zombies (W0 numbers).
 - Visual trade-off: undamaged zombies no longer show a health bar.
 - Editor-mode numbers include EditorLoop/UpdateScene; compare PlayerLoop only. A Development Build was not used.
